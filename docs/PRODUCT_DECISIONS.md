# RP APP 제품 결정 기록

## 2026-08-15

### 프로토타입 상태 변경의 저장 선행 계약

- React 메모리 상태를 먼저 바꾸고 나중에 localStorage에 저장하는 방식은 저장 실패를 성공처럼 보이게 하므로 사용하지 않습니다.
- 모든 사용자 상태 변경은 현재 상태에서 다음 상태를 계산하고 localStorage 쓰기가 성공한 뒤에만 React 화면 상태를 전환합니다.
- 저장 실패 시 기존 화면과 입력값을 유지하고 역할과 경로에 관계없이 상단 경고를 표시합니다. 다음 저장 성공 시 경고를 해제합니다.
- 변경 대상이 없거나 상태 경계 검증을 통과하지 못한 작업은 저장하지 않으며 성공으로 보고하지 않습니다.
- 이 결정은 운영 서버의 트랜잭션·낙관적 동시성·오프라인 큐를 대신하지 않습니다. 서버 전환 시에도 “서버가 확정한 상태와 화면의 성공 상태가 일치한다”는 상위 원칙을 유지합니다.

### 학생 주도 기기 데이터 관리

- 학생은 공개 설정 화면에서 현재 브라우저에 저장된 할 일·일정, 공부·기록, 메시지, 첨부, 사용자 항목과 공개 설정의 범위를 확인합니다.
- 삭제는 즉시 실행하지 않고 삭제 범위와 복구 불가를 먼저 보여준 뒤 화면 안에서 한 번 더 확인합니다.
- 빈 앱 상태를 localStorage에 먼저 저장한 뒤 React 상태를 전환합니다. 저장이 거부되면 화면을 비우지 않아 새로고침 후 샘플 또는 기존 데이터가 되살아나는 오해를 막습니다.
- sessionStorage 초안과 IndexedDB 미디어 삭제는 앱 상태 삭제 뒤 수행하며, 일부 실패는 성공으로 숨기지 않고 범위와 재시도 방법을 표시합니다.
- 프로토타입 삭제는 현재 브라우저 origin에 한정합니다. 운영 계정 삭제·보관 의무·다른 기기 세션·외부 연동 데이터 삭제를 대신하지 않습니다.

### 실제 오늘과 데모 기준일

- 학생 홈과 캘린더의 `오늘`은 브라우저 복원 시 한국 시간(`Asia/Seoul`)의 실제 날짜를 사용합니다.
- 소스의 샘플 데이터는 테스트 재현성을 위해 `2026-08-02`를 기준일로 유지합니다.
- 저장 상태가 구형 기준일에 머물러 있으면 일정·할 일·기록·대화의 상대 간격을 유지해 실제 오늘 주변으로 한 번만 이동합니다.
- 이미 실제 날짜로 사용 중인 상태는 `오늘` 포인터만 갱신하며, 사용자가 만든 일정·기록 날짜를 자동 이동하지 않습니다.
- 서버와 브라우저 시간대 차이로 인한 hydration 불일치를 막기 위해 실제 날짜 계산은 클라이언트 상태 복원 시 수행합니다.

### 수동 기록 데이터 품질 경계

- 시스템 항목은 비교 가능한 의미를 유지하기 위해 단위를 학생이 변경할 수 없게 합니다.
- 집중 공부는 1~720분 정수, 모의고사 점수는 0~100점 소수 2자리, 제자리멀리뛰기는 0~500cm 소수 1자리, 10m 왕복달리기는 1~120초 소수 3자리로 제한합니다.
- 에너지·집중·뻐근함은 1~5 정수, 수면은 0~24시간 소수 2자리로 제한합니다.
- 사용자 정의 항목은 0~1,000,000과 소수 3자리의 넓은 안전 범위를 사용하며 이름·단위를 필수로 합니다. 이 범위는 경기력 평가나 의료 판단 기준이 아니라 잘못된 저장을 막는 데이터 품질 경계입니다.
- 이전 버전의 이상 기록은 자동 삭제·수정하지 않고 `검토 필요`로 격리하며 코치 최신 기록 요약에서 제외합니다.
- 이 프로토타입 규칙은 운영 DB의 종목 코드·측정 프로토콜·코치 검증 상태 설계를 대신하지 않습니다.

## 2026-08-02

### RePERFORMANCE 디지털 생태계 상위 원칙

- RePERFORMANCE 디지털 서비스는 `RP 홈페이지`, `RP 체대입시 홈페이지`, `RP APP`의 세 제품으로 구분합니다.
- RP 홈페이지는 PT·상담 신청으로 이어지는 공익 건강 콘텐츠의 입구이며, 비공개 회원관리 화면으로 확장하지 않습니다.
- RP 체대입시 홈페이지는 RP 홈페이지와 저장소·배포·정보구조를 분리하고, 상담 신청 경로와 브랜드 연결만 유지합니다.
- RP 체대입시 홈페이지는 공식 출처, 기준 연도, 검증일, 변경 이력을 가진 공익 입시 정보 허브를 운영합니다.
- RP 체대입시 홈페이지와 RP APP은 같은 인증 제공자를 사용하는 SSO 구조로 설계하되, 각 서비스의 접근 권한과 세션 검증은 분리합니다.
- RP APP은 입시·학업·운동·회복·소통을 한곳에서 관리해 학생의 디지털 피로를 줄이는 학생관리 앱입니다.
- RP APP이 직접 완성도 있게 제공할 수 있는 핵심 기능은 외부 앱보다 뒤처지지 않게 개발하고, 기기 센서나 독점 데이터처럼 대체할 수 없는 기능은 사용자 동의 후 공식 API로 자동 수집합니다.
- 외부 앱 연동은 화면을 복제하는 플러그인이 아니라 OAuth·공식 API·webhook·운영체제 건강 데이터 허브를 이용하는 `연동 허브`로 구현합니다.
- 입시 정보 허브의 최신 데이터는 RP APP AI와 동일한 버전 관리 지식 저장소에서 사용합니다.
- 입시 데이터 갱신 때마다 모델을 재학습하지 않고, 검색 증강 생성(RAG)으로 최신 자료를 조회하고 답변에 출처·기준 연도·검증일을 표시합니다.
- AI는 합격 보장, 의학적 판단, 자동 훈련 결정의 주체가 아니며 학생과 코치의 판단을 준비하는 보조 도구입니다.
- NORE는 별도 서비스로 유지하며 API, webhook, 자동 데이터 전송을 추가하지 않습니다.

## 2026-08-02

### 학생-코치 대화 미디어 첨부

- 학생과 코치는 1:1 대화에 사진과 영상을 최대 4개까지 첨부할 수 있습니다.
- 프로토타입 파일 원본은 `localStorage`가 아닌 브라우저 `IndexedDB`에 저장하고 메시지 상태에는 메타데이터만 둡니다.
- 사진은 파일당 10MB, 영상은 파일당 50MB, 메시지 합계는 60MB로 제한합니다.
- 브라우저가 제공한 MIME만 신뢰하지 않고 지원 형식별 파일 시그니처를 선택 시점과 로컬 저장 직전에 검사합니다. 여러 파일의 독립적인 내용 검사는 병렬로 실행합니다.
- 서로 다른 localStorage와 IndexedDB를 완전한 단일 트랜잭션으로 묶을 수 없으므로, 프로토타입은 `원본 저장 → 메시지 상태 선영속화 → 화면 상태 전환` 순서와 실패 시 원본 보상 삭제를 사용합니다.
- 시작 시 메시지에서 참조하지 않는 IndexedDB 원본을 삭제하고, 표시 시 크기·MIME·종류·시그니처를 재검증합니다. 참조 원본이 없거나 불일치하면 자동 복구·대체하지 않습니다.
- 파일 시그니처 검사는 단순 위장 파일을 거르는 1차 품질 경계일 뿐 악성 파일 검사나 완전한 디코딩 검증이 아닙니다.
- 사진·영상은 AI 문장 정리 API에 전송하지 않습니다.
- Production은 비공개 객체 저장소와 단기 서명 URL을 사용하며, PostgreSQL에는 객체 키·형식·크기·체크섬·보관 기한만 저장합니다.
- 미디어 첨부에는 별도 동의, 대화 참여자 권한, 서버 재검증, 악성 파일 검사, 삭제 정책이 필요합니다.

## 2026-08-01

### 2차 역할·정보구조

- 학생 주 메뉴는 `오늘·캘린더·기록·상담·코치 대화` 다섯 개로 제한합니다.
- 코치 주 메뉴는 `학생·기록·대화·일정` 네 개로 제한합니다.
- 학부모는 `문의`와 학생이 선택한 `공개 요약`을 분리합니다.
- 관리자는 학생용 앱과 분리된 `운영·관계·AI·감사` 구조를 사용합니다.
- 역할만으로 데이터를 열지 않고 활성 학생-코치·학생-학부모 관계를 함께 확인합니다.
- 관리자도 상담·대화 원문을 기본 조회하지 않으며 안전·보안 사건 접근은 사유를 남깁니다.
- 자세분석, 식단, 멘탈 확장 모델은 핵심 기록 루프와 동의·보관 정책을 검증한 뒤 도입합니다.
- 구조 기준 문서는 `ROLE_PERMISSION_MATRIX.md`, `INFORMATION_ARCHITECTURE.md`, `DATA_MODEL.md`, `CORE_WORKFLOWS.md`입니다.

### PostgreSQL·인증 권한 기반

- 비밀번호와 인증 제공자 토큰은 RP APP DB에 저장하지 않고 `auth_subject`만 연결합니다.
- 역할만으로 학생 데이터를 열지 않고 학생 본인·활성 코치 관계·학생 확인 학부모 관계를 함께 확인합니다.
- 서버 정책과 PostgreSQL RLS를 두 겹으로 적용합니다.
- Runtime DB 역할은 테이블 소유자 또는 `BYPASSRLS` 권한을 갖지 않습니다.
- 연결 풀에서는 트랜잭션 로컬 `rp.user_id`만 사용합니다.
- 학부모는 기본 테이블이 아니라 학생이 허용한 필드만 집계한 요약을 받습니다.
- 메시지는 참여자만 접근하고 본문은 애플리케이션 암호화를 전제로 저장합니다.
- AI 요청은 기능별 승인과 원자적 일일 한도 예약을 통과해야 합니다.
- SQL은 아직 DB에 적용하지 않았으며 인증·DB 제공자 확정 후 테스트 DB에서 먼저 실행합니다.

### 학부모 권한

- 학부모 기본 권한은 코치에게 보내는 `문의 메시지`입니다.
- 출결 확인, 계약·결제 진행 상태, 학업 요약, 실기 기록은 학생이 각각 공개를 허용한 경우에만 표시합니다.
- 공개 설정은 모두 비공개로 시작합니다.
- 학생은 `부모님에게 공개하고 싶은 정보` 화면에서 항목별로 변경할 수 있습니다.
- 전체 대화, 개인 멘탈 기록, 건강·상담 메모, AI 질문 원문은 공개 설정 대상에 포함하지 않습니다.
- 미성년자 계약과 법정대리인 고지 의무는 출시 전에 별도 검토합니다.

### 앱 캘린더와 일정 도우미

- RP APP 안에 공부·운동·상담·시험·회복 일정을 모읍니다.
- 일정 요청은 서버에서 일정 초안으로 해석합니다.
- 사용자가 날짜·시간·제목을 확인한 뒤 한 번의 버튼으로 등록합니다.
- AI나 해석기가 사용자 확인 없이 일정을 확정하지 않습니다.
- 성적·건강·상담 원문은 일정 요청과 제목에 넣지 않습니다.
- 1차 프로토타입은 규칙 기반 해석기를 사용하고, 실제 AI는 인증·승인·사용량 제한 뒤에 연결합니다.

### 학생-코치 대화

- 학생과 담당 코치의 직접 메시지는 학부모 문의와 분리합니다.
- 학부모는 학생-코치 대화 원문을 자동으로 볼 수 없습니다.
- 메시지 작성은 `직접 작성`을 기본값으로 두고 `AI 도움`을 사용자가 선택합니다.
- AI 도움은 문장 초안만 만들며 자동 발송하지 않습니다. 학생 또는 코치가 내용을 확인하고 직접 보냅니다.
- 1차 프로토타입은 외부 모델과 토큰을 사용하지 않는 규칙 기반 정리만 제공합니다.
- 실제 AI는 인증, 관리자 승인, 일일 한도, 민감정보 최소 전송, 사용 기록 정책을 적용한 뒤 연결합니다.
- Production 메시지는 학생-코치 관계 권한, PostgreSQL, 읽음 상태, 알림, 감사 기록을 갖춰야 합니다.
- 현재 로컬 프로토타입의 역할 전환은 기능 시연용이며 권한 보안으로 간주하지 않습니다.

### 수험생 운영체제 경계

- RP APP은 경쟁 앱의 모든 화면과 콘텐츠를 복제하는 슈퍼앱이 아니라, 학생의 계획→실행→기록→피드백→조정을 연결하는 수험생활 운영체제로 설계합니다.
- RP가 직접 제공할 핵심은 오늘 할 일, 주간 계획, 통합 캘린더, 공부 타이머, 성적·오답, 실기 기록, 회복 체크, 코치 대화, 목표 대학 보드와 제한형 AI 조정입니다.
- 학교 시간표·학사일정, 공식 대학 정보, 외부 캘린더, 기기 건강 데이터와 외부 학습 자료는 필요한 요약과 연결만 제공합니다.

- 외부 콘텐츠의 원문을 무단 저장하지 않고 링크·진도·학생 기록만 보관합니다.
