# RP APP 제품 결정 기록

## 2026-08-02

### 학생 홈 집중 구조

- 학생 홈에는 `오늘 상태 저장`, `오늘의 할 일`, `RP AI 도우미` 세 영역만 표시합니다.
- 공부 타이머는 `/student/study`로 분리하고 기록·상담·대화·공개 설정은 사이드바에서 선택합니다.
- 홈의 할 일은 공부·운동·회복별로 보여주며 체크 즉시 완료 상태를 저장합니다.
- 홈은 오늘 행동, 캘린더는 미래 계획과 선택 날짜 편집을 담당합니다.
- 캘린더에 반복되던 대형 오늘·금주 할 일 보드는 제거합니다.

### 사이드바와 RP AI 연결

- 하단 고정 내비게이션 대신 목록 아이콘으로 여는 Notion식 역할별 사이드바를 사용합니다.
- 일정 요청은 URL에 원문을 넣지 않고 브라우저 임시 세션으로 캘린더에 전달합니다.
- 날짜와 시간이 모두 해석되는 홈 일정 요청은 자동 등록하고, 학생이 캘린더에서 즉시 삭제할 수 있게 합니다.
- 입시·운동·식단·멘탈 상담 요청은 자동 답변하지 않고 AI 문장 정리 모드의 담당 코치 대화창으로 연결합니다.
- 밤 10시 격려는 푸시 알림이 아니라 작은 홈 상단 문구부터 적용합니다. 푸시는 사용자 동의와 서버 알림 인프라 이후 검토합니다.

## 2026-08-01

### 2차 역할·정보구조

- 학생 주 메뉴는 `오늘·캘린더·기록·상담·코치 대화` 다섯 개로 제한합니다.
- 코치 주 메뉴는 `학생·기록·대화·일정` 네 개로 제한합니다.
- 학부모는 `문의`와 학생이 선택한 `공개 요약`을 분리합니다.
- 관리자는 학생용 앱과 분리된 `운영·관계·AI·감사` 구조를 사용합니다.
- 역할만으로 데이터를 열지 않고 활성 학생-코치·학생-학부모 관계를 함께 확인합니다.
- 관리자도 상담·대화 원문을 기본 조회하지 않으며 안전·보안 사건 접근은 사유를 남깁니다.
- 자세분석, 식단, 멘탈 확장 모델은 핵심 기록 루프와 동의·보관 정책을 검증한 뒤 도입합니다.
- 구조 기준 문서는 `ROLE_PERMISSION_MATRIX.md`, `INFORMATION_ARCHITECTURE.md`, `DATA_MODEL.md`, `CORE_WORKFLOWS.md`입니다.

### PostgreSQL·인증 권한 기반

- 비밀번호와 인증 제공자 토큰은 RP APP DB에 저장하지 않고 `auth_subject`만 연결합니다.
- 역할만으로 학생 데이터를 열지 않고 학생 본인·활성 코치 관계·학생 확인 학부모 관계를 함께 확인합니다.
- 서버 정책과 PostgreSQL RLS를 두 겹으로 적용합니다.
- Runtime DB 역할은 테이블 소유자 또는 `BYPASSRLS` 권한을 갖지 않습니다.
- 연결 풀에서는 트랜잭션 로컬 `rp.user_id`만 사용합니다.
- 학부모는 기본 테이블이 아니라 학생이 허용한 필드만 집계한 요약을 받습니다.
- 메시지는 참여자만 접근하고 본문은 애플리케이션 암호화를 전제로 저장합니다.
- AI 요청은 기능별 승인과 원자적 일일 한도 예약을 통과해야 합니다.
- SQL은 아직 DB에 적용하지 않았으며 인증·DB 제공자 확정 후 테스트 DB에서 먼저 실행합니다.

### 학부모 권한

- 학부모 기본 권한은 코치에게 보내는 `문의 메시지`입니다.
- 출결 확인, 계약·결제 진행 상태, 학업 요약, 실기 기록은 학생이 각각 공개를 허용한 경우에만 표시합니다.
- 공개 설정은 모두 비공개로 시작합니다.
- 학생은 `부모님에게 공개하고 싶은 정보` 화면에서 항목별로 변경할 수 있습니다.
- 전체 대화, 개인 멘탈 기록, 건강·상담 메모, AI 질문 원문은 공개 설정 대상에 포함하지 않습니다.
- 미성년자 계약과 법정대리인 고지 의무는 출시 전에 별도 검토합니다.

### 공부 타이머

채택하는 패턴:

- 과목과 한 줄 목표
- 25/5, 50/10, 90/20 집중·휴식 프리셋
- 일시정지와 중단 기록
- 자동 세션 기록
- 일·주간 흐름과 계획 대비 실제 수행
- 백그라운드에서도 종료 시각 기준으로 시간 보정

제외하는 패턴:

- 학생 순위와 비교
- 강제 스트릭
- 카메라·화면·위치 감시
- 중단을 실패로 표시하는 문구
- 첫 화면의 과도한 통계

참고한 공개 기능 설명:

- Focus: 유연한 세션, 휴식, 과목·라벨, 주간 통계, 계획 대비 실제 흐름
- Todak Time: 과목별 기록, 순위·비교 없는 설계, 앱 종료 시 세션 안정성
- Study Timer: 자동 기록, 공부 캘린더, 시험 D-day, 집중·휴식 전환

### 앱 캘린더와 일정 도우미

- RP APP 안에 공부·운동·상담·시험·회복 일정을 모읍니다.
- 일정 요청은 서버에서 일정 초안으로 해석합니다.
- 사용자가 날짜·시간·제목을 확인한 뒤 한 번의 버튼으로 등록합니다.
- AI나 해석기가 사용자 확인 없이 일정을 확정하지 않습니다.
- 성적·건강·상담 원문은 일정 요청과 제목에 넣지 않습니다.
- 1차 프로토타입은 규칙 기반 해석기를 사용하고, 실제 AI는 인증·승인·사용량 제한 뒤에 연결합니다.

### 학생-코치 대화

- 학생과 담당 코치의 직접 메시지는 학부모 문의와 분리합니다.
- 학부모는 학생-코치 대화 원문을 자동으로 볼 수 없습니다.
- 메시지 작성은 `직접 작성`을 기본값으로 두고 `AI 도움`을 사용자가 선택합니다.
- AI 도움은 문장 초안만 만들며 자동 발송하지 않습니다. 학생 또는 코치가 내용을 확인하고 직접 보냅니다.
- 1차 프로토타입은 외부 모델과 토큰을 사용하지 않는 규칙 기반 정리만 제공합니다.
- 실제 AI는 인증, 관리자 승인, 일일 한도, 민감정보 최소 전송, 사용 기록 정책을 적용한 뒤 연결합니다.
- Production 메시지는 학생-코치 관계 권한, PostgreSQL, 읽음 상태, 알림, 감사 기록을 갖춰야 합니다.
- 현재 로컬 프로토타입의 역할 전환은 기능 시연용이며 권한 보안으로 간주하지 않습니다.

## 2026-08-02

### 수험생 운영체제 경계

- RP APP은 경쟁 앱의 모든 화면과 콘텐츠를 복제하는 슈퍼앱이 아니라, 학생의 계획→실행→기록→피드백→조정을 연결하는 수험생활 운영체제로 설계합니다.
- RP가 직접 제공할 핵심은 오늘 할 일, 주간 계획, 통합 캘린더, 공부 타이머, 성적·오답, 실기 기록, 회복 체크, 코치 대화, 목표 대학 보드와 제한형 AI 조정입니다.
- 학교 시간표·학사일정, 공식 대학 정보, 외부 캘린더, 기기 건강 데이터와 외부 학습 자료는 필요한 요약과 연결만 제공합니다.
- 동영상 강의 원본, 대규모 문제은행, 실제 원서접수·결제, 의료·심리 진단과 치료는 검증된 외부 서비스를 유지합니다.
- 외부 콘텐츠의 원문을 무단 저장하지 않고 링크·진도·학생 기록만 보관합니다.
- NORE API 호출과 자동 데이터 전송은 추가하지 않습니다.

### 기능 확장 순서

- 새 화면을 늘리기 전에 실제 인증, 테스트 DB, RLS, 여러 기기 동기화와 알림 기반을 먼저 완성합니다.
- 첫 사용자 기능 확장은 주간 계획과 통합 수집함으로 하며, 오늘 화면의 세 영역 구조는 유지합니다.
- 할 일, 타이머, 캘린더와 학습 항목은 같은 ID와 상태를 참조해 중복 입력을 막습니다.
- 그다음 과목·시험·성적·오답·질문 보관함과 체대입시 종목 사전·측정 프로토콜을 구축합니다.
- AI는 일정과 기록의 초안·요약·재배치만 제안하고, 저장·전송·운동 강도 변경은 학생 또는 코치가 확인합니다.
- 기능 설계의 상세 기준은 `RP_APP_STUDENT_APP_BENCHMARK_AND_INTEGRATION_REPORT.md`를 따릅니다.
