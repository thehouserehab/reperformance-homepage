# RP APP 수험생 앱 벤치마크 및 통합 기능 설계 보고서

**기준일:** 2026-08-02  
**대상:** 체대입시 학생, 코치, 학생이 선택적으로 정보를 공개한 학부모  
**목적:** 수험생이 여러 앱을 오가며 생기는 관리 피로를 줄이고, RP APP 하나에서 공부·실기·회복·입시·소통의 하루 흐름을 운영할 수 있도록 기능 확장 기준을 정한다.

## 1. 결론

RP APP의 목표는 `기존 앱의 모든 콘텐츠를 복제하는 슈퍼앱`이 아니라 `수험생활을 조정하는 학생 운영체제`가 되어야 한다.

학생이 여러 앱을 쓰는 근본 이유는 기능이 부족해서가 아니라 데이터와 행동이 서로 연결되지 않기 때문이다. 학교 일정은 시간표 앱, 공부 계획은 플래너, 집중 시간은 타이머, 성적은 입시 서비스, 실기는 코치 메모, 식단과 수면은 건강 앱, 질문은 카카오톡에 흩어진다. RP APP은 이 데이터를 한 화면에 모두 펼쳐놓는 대신 다음 하나의 순환으로 연결해야 한다.

> 계획 수집 → 오늘 우선순위 결정 → 공부·운동 실행 → 성적·실기·상태 기록 → 코치 피드백 → 다음 계획 자동 조정

따라서 기능 전략은 세 단계로 구분한다.

1. **RP가 직접 제공:** 오늘 할 일, 주간 계획, 통합 캘린더, 공부 타이머, 성적·오답 기록, 실기 기록, 회복 체크, 코치 대화, 목표 대학 보드, AI 일정 조정.
2. **RP가 연결·요약:** 학교 시간표·학사일정, 기기 건강 데이터, 공식 대학 정보, 외부 학습 콘텐츠, 외부 캘린더.
3. **외부 서비스 유지:** 동영상 강의 원본, 대규모 문제은행, 실제 원서접수·결제, 의료·심리 진단, 치료와 처방.

이 경계를 지키면 학생은 RP APP에서 “오늘 무엇을 해야 하는지”를 해결하면서도, 공식성과 전문성이 필요한 순간에는 검증된 원천으로 이동할 수 있다.

## 2. 현재 RP APP 진단

### 2.1 이미 확보한 강점

- 학생 홈이 `오늘 상태 저장`, `오늘의 할 일`, `RP AI 도우미` 세 영역으로 제한되어 있다.
- 공부·운동·회복을 같은 날짜 기반 할 일로 관리한다.
- 주간·월간 캘린더, 공부 타이머, 학생·코치 대화, 상담 허브가 분리되어 있다.
- 성적, 실기 기록, 조건 체크, 학부모 공개 설정의 데이터 구조가 일부 설계되어 있다.
- 학생이 허용한 정보만 학부모에게 공개하는 제품 원칙이 명확하다.
- AI는 자동 발송·자동 판단이 아니라 초안과 준비를 돕는 방향으로 제한되어 있다.
- PostgreSQL, RLS, AI 승인·일일 한도 구조가 설계되어 있다.

### 2.2 아직 프로토타입인 부분

- 데이터가 브라우저 `localStorage`에 저장되어 계정·기기 간 동기화가 없다.
- 실제 인증, PostgreSQL 마이그레이션 적용, 실시간 메시지, 푸시 알림이 없다.
- 성적과 실기 기록은 데이터 구조에 비해 입력·분석 흐름이 얕다.
- 반복 일정, 주간 계획, 미완료 일정 재배치, 시험 D-day가 없다.
- 학교 시간표·학사일정·급식, 외부 캘린더, 건강 데이터 연결이 없다.
- 오답노트, 복습 큐, 과목·단원 목표, 질문 보관함이 없다.
- 훈련 루틴, 세트·시도별 기록, 측정 프로토콜, 영상 피드백이 없다.
- 입시 목표 대학을 성적·실기·준비 일정과 연결하는 학생용 작업 공간이 없다.
- AI는 규칙 기반 초안 수준이며 학생 전체 맥락을 이용하지 않는다.

### 2.3 완성도 판단

현재 RP APP은 방향이 좋은 `상호작용 가능한 제품 구조 시제품`이다. 기능 수보다 먼저 실제 계정·DB·동기화·알림을 완성하지 않으면 기능을 추가할수록 서로 다른 화면에 임시 데이터가 쌓여 다시 디지털 피로가 생긴다.

## 4. 앱별 핵심 학습점

### 4.1 계획·타이머

**열품타**는 과목별 시간 측정, 플래너, 스터디그룹, 학교 시간표·급식을 한 앱에 모은다. 학생에게 중요한 것은 순위 자체보다 `지금 공부 시작 → 과목별 누적 → 오늘 계획 확인`이 한 흐름이라는 점이다. RP는 그룹 순위와 캠스터디 감시는 제외하고, 타이머가 시작되면 선택한 오늘 할 일과 자동 연결해야 한다.

**투두메이트**는 간단한 체크, 루틴, 위젯, 다른 사람과의 가벼운 응원을 제공한다. RP는 친구 공개 피드 대신 코치가 배정한 항목과 학생이 만든 항목을 명확히 구분하고, 홈 위젯 또는 PWA 바로가기에서 한 번에 체크할 수 있어야 한다.

**Notion**은 같은 데이터를 목록·보드·캘린더 등 다른 보기로 재사용하고, 항목을 상세 페이지로 확장한다. RP도 할 일 데이터를 홈, 주간 계획, 캘린더에서 중복 생성하지 않고 같은 항목을 서로 다른 밀도로 보여줘야 한다.

**Google Calendar와 Focus To-Do**는 마감일, 반복, 하위 작업, 알림, 시간 블록, 실제 집중시간을 연결한다. RP에 필요한 것은 복잡한 프로젝트 관리가 아니라 `해야 할 일`과 `실제로 확보한 시간`의 차이를 보여주는 기능이다.

**Forest와 Digital Wellbeing**은 집중 중 방해 앱을 줄인다. 웹/PWA만으로 iOS·Android 전체 앱을 안정적으로 차단하기는 어렵다. RP는 1차로 방해 금지 안내와 집중 세션을 제공하고, 네이티브 앱 단계에서 운영체제 집중 모드 연동을 검토한다.

### 4.2 학교·학습

**학교생활 앱**은 시간표, 급식, 학사일정을 매일 첫 화면에서 빠르게 보여준다. RP에는 학교를 선택하면 NEIS 공개 API 기반 학사일정과 급식을 불러오되, 홈에는 다음 수업·훈련에 영향을 주는 정보만 요약해야 한다.

**메가스터디·EBSi**는 강의 수강, 학습 목표, 모의고사 채점·분석, 입시 정보를 연결한다. RP가 강의 플랫폼까지 만들 필요는 없다. 대신 학생이 외부 강의나 교재를 `학습 자원`으로 등록하고 진도, 계획, 실제 집중시간을 관리하도록 한다.

**오르조**는 기출 탐색, 자동 채점, 문항별 시간, 오답 복습, 필기를 연결한다. RP의 핵심 적용점은 문제 원문 보유가 아니라 `시험 결과 → 틀린 단원 → 복습 날짜 → 질문`의 연결이다.

**콴다**는 사진 기반 문제 질문, 단계별 풀이, 선생님 Q&A, 퀴즈 생성을 제공한다. RP AI가 무제한 문제풀이를 대신하면 비용과 정확성 문제가 커진다. RP에서는 풀이 생성보다 `모르는 문제 사진·과목·단원·내 시도`를 질문 보관함에 넣고 코치 또는 외부 학습 서비스로 전달하는 기능이 우선이다.

**Quizlet·Khan Academy**의 공통점은 작은 단위의 반복 연습과 숙련도 가시화다. RP에는 학생이 오답이나 암기 항목을 카드로 저장하고 `오늘 복습할 항목`만 받는 간단한 간격 반복 큐가 적합하다.

### 4.3 입시

**대입정보포털 어디가**는 학생부·수능·모의고사 성적과 대학·학과·전형을 연결하며, 대학별 산출 방식이 달라 직접 비교할 수 없음을 명시한다. RP는 공식 정보를 원천으로 표시하고, 출처·학년도·확인일을 데이터와 함께 보존해야 한다.

**진학사**는 성적 입력, 추천 대학, 모의지원, 경쟁자 분포와 합격예측을 제공하지만 실기·면접·서류 등으로 실제 결과가 달라질 수 있음을 안내한다. RP의 예측 기능도 하나의 합격 확률 숫자보다 `성적 위치`, `실기 위치`, `변동 요인`, `확인 필요 항목`을 분리해서 보여주는 것이 안전하다.

**유웨이어플라이**는 실제 원서 작성·보관·결제를 담당한다. RP는 지원 후보, 마감일, 준비 서류, 접수 여부 체크리스트를 관리하되 원서 내용이나 결제 정보를 복제 저장하지 않고 공식 접수 페이지로 연결한다.

### 4.4 운동·실기·영상

**플랜핏·Hevy**는 루틴 생성, 운동 기록, 이전 기록 불러오기, 진행 그래프를 쉽게 만든다. RP는 일반 헬스 종목보다 체대입시 실기 종목을 중심으로 `준비운동 → 기술 훈련 → 측정 → 보강 → 회복` 세션 템플릿을 제공해야 한다.

**OnForm·Dartfish·CoachNow**는 영상 촬영, 프레임 단위 재생, 좌우 비교, 선·각도 표시, 음성 피드백, 코치 대화를 결합한다. RP의 1차 구현은 자동 자세 진단이 아니라 다음 기능이어야 한다.

- 학생이 정해진 촬영 가이드에 맞춰 영상을 업로드한다.
- 코치가 구간, 기준선, 간단한 도형과 텍스트·음성 피드백을 남긴다.
- 같은 종목의 이전 영상과 나란히 비교한다.
- 분석 결과는 의료 진단이나 자동 운동 처방으로 표현하지 않는다.

**HomeCourt**는 카메라로 반복 수행을 감지하고 즉시 피드백한다. 장기적으로 RP도 제자리멀리뛰기, 왕복달리기처럼 측정 프로토콜이 명확한 종목부터 보조 측정을 검토할 수 있다. 다만 실제 입시 기록으로 인정하려면 촬영 조건, 거리 보정, 기기 오차, 코치 검증이 필요하다.

### 4.5 회복·식단·멘탈

**Samsung Health·Apple Health**는 수면, 활동, 심박 등 여러 출처의 데이터를 사용자 권한 아래 모은다. RP는 모든 건강 데이터를 수집하지 말고, 학생이 허용한 `수면 시간`, `활동·운동 시간`, `안정 시 심박 추세`처럼 훈련 계획에 필요한 최소 요약만 읽는 방향이 적절하다.

**MyFitnessPal**은 음식·수분·운동 기록과 영양 요약을 제공한다. 미성년 체대입시생에게 칼로리 제한과 체중 감량을 강하게 제시하면 위험하다. RP는 음식 사진, 식사 누락 여부, 수분, 훈련 전후 섭취 확인과 코치 코멘트를 우선하고, 질환·섭식 문제·극단 감량은 전문가에게 연결한다.

**Headspace·트로스트**는 짧은 명상, 수면·스트레스 지원, 감정 기록, 전문가 상담을 제공한다. RP는 심리치료 앱이 아니라 `오늘 부담 정도`, `도움이 필요한 주제`, `지금 연락할 사람`을 빠르게 선택하게 하고 위기 신호는 사람에게 연결해야 한다.

### 4.6 소통·보호자

**Google Classroom과 단체 커뮤니케이션 앱**의 장점은 과제·공지·피드백을 대화와 분리하는 것이다. RP도 모든 것을 하나의 채팅에 넣지 말고 다음을 구분해야 한다.

- 일정 변경과 공지
- 과제·운동 처방에 붙는 코치 피드백
- 학생이 보내는 질문
- 민감한 1:1 상담
- 학생이 허용한 학부모 주간 요약

학부모는 학생-코치 대화 원문을 볼 수 없어야 하며, 학생이 공개한 출결·계약 진행·학업·실기 요약만 확인한다.

## 5. RP APP 목표 기능 구조

학생 홈의 세 영역은 유지한다. 기능이 늘어도 홈을 대시보드로 비대하게 만들지 않는다.

### 5.1 홈

1. **오늘 상태 저장:** 에너지, 집중, 근육통과 선택형 수면·스트레스 확인.
2. **오늘의 할 일:** 공부·운동·회복 중 각 영역의 최우선 항목만 표시.
3. **RP AI 도우미:** 일정 등록, 계획 조정, 질문 정리, 기록 찾기, 코치 상담 연결.

홈 아래에 새 카드를 계속 추가하지 않는다. 새 기능은 사이드바와 상세 화면으로 이동하고, 홈에는 행동이 필요한 예외만 올라온다.

### 5.2 사이드바 정보구조

| 그룹 | 메뉴 | 역할 |
|---|---|---|
| 오늘 | 오늘 | 상태, 최우선 할 일, AI 도우미 |
| 계획 | 캘린더, 주간 계획, 입시 일정 | 학교·공부·운동·시험·지원 마감 통합 |
| 실행 | 공부, 실기 훈련, 회복 | 타이머, 루틴, 세션 실행 |
| 기록 | 성적·오답, 실기 기록, 컨디션 | 변화 기록과 복습·보완 항목 |
| 도움 | 코치 대화, 상담, 알림함 | 질문, 피드백, 중요한 안내 |
| 설정 | 부모님 공개, 알림, 연결 서비스 | 권한과 개인정보 제어 |

모바일에서는 한 번에 5~6개 메뉴를 펼치지 않고 그룹을 접고 펼치는 구조를 사용한다.

## 6. 신규 기능 상세안

### 6.1 통합 수집함

학생이 떠오른 일을 분류하느라 멈추지 않도록 한 줄로 입력한다.

- 예: “영어 3강 금요일까지”, “다음 주 제멀 측정”, “전북대 서류 확인”.
- RP AI가 공부·운동·입시·회복으로 분류하고 날짜·소요시간 초안을 만든다.
- 학생이 확인해야만 저장한다. 날짜가 불명확하면 수집함에 남긴다.
- 모바일 공유 기능으로 외부 웹페이지·강의 링크·문제 사진을 수집함에 보낼 수 있게 한다.

### 6.2 주간 계획과 자동 재배치

- 이번 주 공부 목표, 운동 세션, 회복 목표를 각각 최대 3개로 제한한다.
- 학교·훈련·상담처럼 고정된 일정 주변에 공부 시간 블록을 배치한다.
- 미완료 항목은 다음 날로 무조건 넘기지 않고 `다시 배치`, `분량 축소`, `취소`, `코치에게 도움 요청` 중 선택한다.
- 연속 고강도 훈련, 수면 부족, 시험 직전 일정 충돌을 경고한다.
- 일요일 또는 사용자가 정한 요일에 계획 대비 실제 수행과 다음 주 조정안을 보여준다.

### 6.3 학교생활 연결

- 학교·학년·반을 학생이 선택적으로 등록한다.
- NEIS 공개 API에서 시간표, 학사일정, 급식 정보를 가져온다.
- 시험 기간과 학교 행사는 캘린더에 초안으로 제안하고 학생이 반영 여부를 결정한다.
- 급식은 식단 처방이 아니라 훈련 전후 식사 준비 판단을 돕는 참고 정보로만 사용한다.
- 학교 데이터가 없거나 잘못되면 수동 일정으로 대체할 수 있어야 한다.

### 6.4 과목·진도 관리

- 과목 → 교재·강의 → 단원 → 학습 항목의 4단계 구조를 제공한다.
- 각 항목에는 목표 분량, 예상 시간, 실제 시간, 완료 상태, 이해도를 기록한다.
- 외부 강의·교재는 링크와 진도만 저장하고 콘텐츠 원본은 저장하지 않는다.
- 타이머 시작 시 오늘의 학습 항목을 선택하면 실제 시간이 자동 누적된다.
- 코치는 전체 공부 내용을 감시하지 않고, 학생이 공유한 목표와 주간 요약만 본다.

### 6.5 시험·성적 관리

- 내신, 모의고사, 수능, 면접, 수행평가를 구분한다.
- 과목별 원점수, 등급, 백분위·표준점수 중 해당 시험에 필요한 값만 입력한다.
- 시험 전 목표와 시험 후 결과를 연결한다.
- 성적 변화는 단순 순위가 아니라 목표 대학 반영 방식과 연결해 해석한다.
- 성적표 사진 OCR은 후순위로 두고, 첫 버전은 수동 입력과 검증 가능한 가져오기부터 시작한다.

### 6.6 오답·복습 큐

- 문제 사진 또는 출처, 과목, 단원, 틀린 이유, 다음 복습일을 저장한다.
- 틀린 이유는 `개념 부족`, `조건 해석`, `계산`, `시간 부족`, `실수`, `미분류`로 시작한다.
- 복습 완료 시 `다시 틀림`, `도움 필요`, `이해`, `숙달`을 선택한다.
- 간격 반복은 학생의 응답에 따라 다음 복습일을 조정한다.
- AI는 정답만 주기보다 학생의 시도와 막힌 지점을 먼저 묻는다.
- 문제 원문 저장과 공유는 저작권·보관 정책을 별도로 검토한다.

### 6.7 질문 보관함

- 공부, 실기, 입시, 식단, 멘탈 질문을 한 곳에 임시 저장한다.
- 질문에는 사진·영상·관련 기록을 연결할 수 있다.
- AI가 질문을 정리하되 자동 발송하지 않는다.
- 코치에게 보낼 질문, 외부 과목 선생님에게 물을 질문, 스스로 더 확인할 질문을 구분한다.
- 답을 받으면 해당 오답·훈련·입시 목표에 연결해 다시 찾을 수 있게 한다.

### 6.8 체대입시 실기 훈련

- 대학별 실기 종목과 별개로 표준 종목 사전을 둔다.
- 종목마다 단위, 측정 방법, 유효·무효 조건, 장비, 성별·연도 기준을 관리한다.
- 코치가 훈련 계획을 배정하면 학생은 세션에서 준비운동, 세트·횟수·거리·시간, RPE, 통증 여부를 기록한다.
- 이전 기록을 기본값으로 불러와 입력 부담을 줄인다.
- 측정 기록은 `학생 기록`, `코치 확인`, `공식 측정`으로 출처를 구분한다.
- 그래프는 개인의 기준선·최고·최근·목표만 보여주고 다른 학생 순위는 기본 제공하지 않는다.
- 종목별 기록이 목표 대학 기준에서 어느 구간인지 보여주되 합격을 단정하지 않는다.

### 6.9 영상 피드백

- 종목별 전면·측면 촬영 가이드와 개인정보 동의를 먼저 제공한다.
- 영상 업로드 시 종목, 시도 번호, 촬영 각도, 측정일을 태깅한다.
- 코치는 느린 재생, 구간 지정, 선·각도, 텍스트와 음성 피드백을 남긴다.
- 이전 영상과 좌우 비교하고 코치가 지정한 한두 개의 교정 포인트만 다음 할 일로 만든다.
- 보관 기간, 다운로드 권한, 삭제, 학부모 공개 금지를 명확히 한다.
- 자동 관절 추정과 자세 분석은 종목별 검증 데이터가 확보된 뒤 보조 기능으로 제한한다.

### 6.10 회복과 부상 신호

- 매일 에너지, 집중, 근육통에 수면 시간과 통증 부위를 선택적으로 추가한다.
- 운동 전에는 통증 악화, 어지럼, 흉통 등 안전 질문을 짧게 확인한다.
- 이상 신호가 있으면 운동 강도를 AI가 임의 변경하지 않고 코치 확인을 요청한다.
- 훈련 후 RPE와 회복 행동을 기록하고 다음 고강도 세션까지 회복 시간을 확인한다.
- 학생의 상태를 `준비 점수` 하나로 단정하지 않고 원인이 되는 항목을 각각 보여준다.

### 6.11 식사·수분

- 음식 사진, 식사 시각, 식사 거름, 수분, 훈련 전후 섭취를 빠르게 기록한다.
- 칼로리·체중 감량 중심 화면은 기본으로 두지 않는다.
- AI는 일반적인 준비 질문과 패턴 요약만 제공한다.
- 알레르기, 질환, 섭식 문제, 빠른 체중 변화는 영양사·의료진 확인을 안내한다.
- 코치는 생활 패턴과 훈련 일정에 관한 코멘트만 남긴다.

### 6.12 멘탈·부담 관리

- 하루 한 번 부담 정도와 주된 원인을 선택적으로 기록한다.
- `혼자 정리`, `코치에게 말하기`, `보호자·신뢰하는 사람에게 말하기`, `전문 도움 찾기`를 선택한다.
- 짧은 호흡·정리 콘텐츠는 제공할 수 있지만 진단명, 치료 효과, 심리 점수 순위를 제공하지 않는다.
- 자해·극단 선택·학대 등 위기 표현은 일반 AI 답변을 중단하고 즉시 사람과 긴급 지원 정보로 연결한다.
- 개인 멘탈 기록은 학부모 공개 항목에 포함하지 않는다.

### 6.13 목표 대학 작업 공간

- 대학 → 모집단위 → 전형을 개별 목표 항목으로 저장한다.
- 각 목표에 공식 모집요강 링크, 학년도, 전형 요소, 성적 반영, 실기 종목, 마감일, 확인일을 둔다.
- 학생의 현재 성적·실기 기록과 연결하되 서로 다른 연도·성별·측정 방식의 기준을 합치지 않는다.
- 결과는 `현재 강점`, `보완 우선순위`, `변동 요인`, `코치와 확인할 질문`으로 표현한다.
- 확률을 제공한다면 입력 범위, 표본, 갱신일, 실기·면접·학생부 미반영 가능성과 실제 결과 차이를 같은 화면에 표시한다.

### 6.14 지원 일정·서류 체크리스트

- 원서접수, 서류 제출, 실기일, 면접일, 합격 발표를 캘린더와 연결한다.
- 전형별 준비 서류와 확인 상태를 관리한다.
- 민감한 서류 원본은 저장하지 않고 `준비 전`, `준비 중`, `제출 확인` 상태와 외부 보관 위치만 기록한다.
- 접수 마감 전 알림은 학생이 반드시 확인해야 하는 높은 우선순위로 분류한다.
- 실제 접수와 결제는 유웨이·진학어플라이 등 공식 서비스에서 진행한다.

### 6.15 코치 피드백 허브

- 코치는 학생별 오늘 위험 신호, 답장 대기, 기록 검토 대기, 일정 충돌만 먼저 본다.
- 과제·훈련·영상·성적 기록 각각에 문맥형 코멘트를 남긴다.
- 중요한 결정은 채팅에서 사라지지 않도록 `다음 행동`으로 고정한다.
- 학생은 피드백을 확인하고 `이해`, `질문 있음`, `수정 요청`으로 응답한다.
- AI는 주간 기록을 요약하고 답장 초안을 만들지만 최종 판단과 전송은 코치가 한다.

### 6.16 알림·집중 정책

알림은 앱 체류 시간을 늘리는 도구가 아니라 다음 행동을 놓치지 않게 하는 도구로 제한한다.

| 기본 즉시 알림 | 기본 요약 알림 | 기본 끔 |
|---|---|---|
| 코치 답장, 일정 변경, 상담·실기·원서 마감, 안전 확인 | 오늘 계획, 주간 검토, 미확인 질문 | 순위, 연속 기록 압박, 홍보, 일반 명언 |

- 취침 시간, 학교 수업 시간, 훈련 시간에는 조용한 시간을 적용한다.
- 밤 10시 격려는 사용자가 선택한 경우에만 작은 앱 내 문구 또는 묶음 알림으로 제공한다.
- 완료하지 못한 일을 반복해서 독촉하지 않는다.
- 네이티브 앱 단계에서 iOS 집중 모드·Screen Time, Android Digital Wellbeing으로 이동하는 설정 안내를 제공한다.

## 7. RP AI 도우미 설계

### 7.1 하나의 입력창, 여러 제한된 도구

학생에게 여러 AI 챗봇을 만들지 않는다. 하나의 RP AI 도우미가 요청 의도를 분류하고 승인된 도구만 호출한다.

| 요청 | AI 처리 | 최종 확정 |
|---|---|---|
| “내일 영어 40분 넣어줘” | 일정 초안·충돌 확인 | 날짜·시간이 명확하면 등록 후 되돌리기 제공 |
| “오늘 너무 피곤해” | 상태 저장 제안, 일정 분량 조정안 | 학생 선택, 위험 신호는 코치 확인 |
| “전북대 준비 뭐부터?” | 공식 데이터와 학생 기록을 분리해 질문·우선순위 정리 | 코치 검토 |
| “제멀 기록이 안 올라” | 최근 기록·훈련·회복 변화 요약 | 코치가 훈련 방향 결정 |
| “수학 이 문제 모르겠어” | 학생의 시도·단원·질문 정리 | 외부 풀이 또는 사람에게 질문 |
| “코치님께 말해줘” | 메시지 초안 | 학생이 확인 후 직접 전송 |

### 7.2 비용 통제

- 관리자 승인을 받은 학생만 토큰 사용 AI를 쓴다.
- 기능별 일일 횟수와 토큰 상한을 둔다.
- 일정 분류, 단순 요약, 반복 일정은 규칙 기반 또는 소형 모델을 우선한다.
- 긴 대화 전체를 매번 보내지 않고 구조화된 요약과 필요한 기록만 전달한다.
- 같은 공식 입시 자료는 검색 인덱스와 캐시를 사용한다.
- 사용자에게 남은 사용량과 제한 이유를 명확히 보여준다.

### 7.3 안전·정확성

- 입시 결과, 의료·심리 상태, 운동 처방을 AI가 확정하지 않는다.
- 공식 대학 정보에는 출처·학년도·확인일을 표시한다.
- 성적·건강·영상 원문은 필요한 기능에만 최소 전송한다.
- AI 결과를 부모에게 자동 공개하지 않는다.
- 코치가 본 AI 요약과 학생 원문을 구분한다.

현재 `tasks`, `study_sessions`, `academic_snapshots`, `practical_records`, `calendar_events`, `admission_profiles`를 유지하고 다음 묶음을 추가하는 것이 적절하다.

| 훈련 계획·세션 | 목표, 종목, 세트, RPE, 통증, 완료 | 코치 배정과 학생 수정 권한 분리 |

| 회복 기록 | 수면, 통증 부위, RPE, 회복 행동 | 의료 데이터 최소화 |

하나의 사실을 여러 테이블에 복사하지 않는다. 예를 들어 공부 할 일과 타이머 세션은 서로 참조하고, 실기 측정과 대학 기준도 종목 코드로 연결한다.

## 9. 외부 연동 판단

### 9.1 우선 검토

- **NEIS 공개 API:** 시간표·급식·학사일정. 학교 공개 데이터만 사용한다.
- **외부 캘린더:** 학생이 선택한 일정의 가져오기·내보내기. 양방향 충돌 규칙이 필요하다.
- **Android Health Connect·Apple HealthKit:** 수면·활동 요약을 항목별 동의 후 읽는다.
- **공식 대학 자료 링크:** ADIGA와 대학 입학처 원문으로 이동한다.
- **PWA 푸시:** 코치 답장, 일정 변경, 마감 알림부터 제한적으로 적용한다.

### 9.2 후순위

- 성적표 OCR과 자동 과목 매핑
- 운동 영상 자동 관절 추정
- 웨어러블 실시간 심박 기반 훈련 제어
- 외부 문제풀이 서비스 API
- 캘린더 완전 양방향 동기화

### 9.3 하지 않을 것

- NORE API 호출이나 데이터 전송
- 원서접수·결제 기능 복제
- 외부 강의·문제·모집요강의 무단 저장
- 학생 동의 없는 학부모 감시
- AI 합격 보장, 의료·심리 진단, 자동 운동 처방
- 과도한 순위·스트릭·벌점과 카메라 감시

## 11. 다음 개발 작업 순서

내일 바로 화면을 늘리기보다 아래 순서로 시작한다.

1. **제품 범위 확정:** 이 보고서의 `직접 제공·연결·외부 유지` 경계를 제품 결정 문서에 반영한다.
2. **핵심 데이터 연결:** 할 일, 타이머, 캘린더, 학습 항목이 같은 ID와 상태를 사용하도록 모델을 확장한다.
3. **주간 계획 화면:** 오늘 화면은 유지하고 사이드바에 주간 계획을 추가한다.
4. **통합 수집함:** 자연어 입력을 일정·할 일 초안으로 분류하고 사용자 확인 후 저장한다.
5. **서버 기반 작업 착수:** 인증·테스트 DB·RLS를 실제로 적용한다. 이후 새 기능은 서버 데이터 기준으로 개발한다.
6. **학업 관리 설계:** 과목·교재·단원·시험·오답의 최소 스키마와 화면 흐름을 확정한다.
7. **실기 기록 설계:** 종목 사전과 측정 프로토콜부터 만들고 대학별 기준 데이터와 연결한다.

첫 구현 단위는 `주간 계획 + 통합 수집함 + 서버 저장 기준`이 가장 적절하다. 이 세 가지가 이후 공부·실기·입시 기능이 같은 일정 체계 위에서 움직이게 만든다.

## 12. 출시 판단 기준

### 학생

- 아침 30초 안에 오늘 공부·운동·회복 우선순위를 이해한다.
- 할 일, 캘린더, 타이머, 기록 사이에 같은 내용을 반복 입력하지 않는다.
- 미완료 계획을 죄책감 표현 없이 다시 조정한다.
- 입시·실기·학업 질문을 어디에 저장하고 누구에게 보낼지 명확하다.

### 코치

- 학생의 모든 데이터를 훑지 않고 오늘 개입할 학생을 찾는다.
- 훈련 기록, 상태, 질문, 영상에 문맥형 피드백을 남긴다.
- AI 요약을 참고하되 최종 판단을 직접 한다.

### 학부모

- 기본 기능은 코치 문의이며 학생이 공개한 요약만 본다.
- 민감한 대화·멘탈·건강 기록은 볼 수 없다.

### 운영·기술

- 실제 인증, DB, RLS, 감사 로그, 삭제와 보관 정책이 작동한다.
- AI 사용은 승인·일일 한도·비용 기록을 통과한다.
- 공식 입시 데이터에는 출처·학년도·확인일이 있다.
- 모바일에서 오늘 행동까지 2번 이상의 메뉴 이동이 필요하지 않다.
- 핵심 일정과 기록은 네트워크가 잠시 끊겨도 유실되지 않는다.

## 14. 최종 제안

RP APP의 차별점은 “기능이 가장 많은 앱”이 아니라 “공부와 실기를 동시에 해야 하는 학생의 계획을 실제 코치 관리와 연결하는 앱”이다.

최종 제품은 다음 질문에 빠르게 답해야 한다.

- 오늘 공부·운동·회복 중 무엇을 먼저 해야 하는가?
- 계획한 것과 실제로 한 것은 어떻게 다른가?
- 성적과 실기 중 지금 가장 큰 제약은 무엇인가?
- 피로·통증·부담 때문에 계획을 조정해야 하는가?
- 혼자 해결할 일과 코치에게 물을 일은 무엇인가?
- 목표 대학을 위해 다음 한 주에 무엇을 바꿔야 하는가?

이 여섯 질문을 같은 기록에서 답할 수 있으면 학생은 여러 플래너와 메신저를 오갈 필요가 크게 줄어든다. 반대로 각 경쟁 앱의 메뉴를 모두 복제하면 RP APP 자체가 또 하나의 피로한 앱이 된다. 따라서 `한 번 입력하고 여러 맥락에서 재사용`, `오늘은 세 가지 행동만`, `AI보다 사용자와 코치가 최종 결정`을 계속 제품의 중심 원칙으로 유지해야 한다.
