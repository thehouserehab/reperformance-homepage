# RP APP

체대입시 학생이 공부, 운동, 회복과 상담을 한 흐름에서 관리하도록 돕는 역할 기반 PWA입니다.

## 현재 단계

현재 코드는 **2차 역할·정보구조 위에 PostgreSQL 마이그레이션과 활성 관계 기반 권한 계약을 추가한 단계**입니다.

- 학생 홈을 `오늘 상태 저장·오늘의 할 일·RP AI 도우미` 세 영역으로 제한
- 홈에서 공부·운동·회복 할 일 체크 완료
- 별도 화면의 공부 타이머
- 캘린더 선택 날짜에서 공부·운동·회복 할 일 추가·삭제·완료
- 홈의 자연어 요청을 확인형 일정 초안 또는 코치 대화로 연결하는 RP AI 도우미
- 모바일 주간·데스크톱 월간 캘린더 전환
- 학생 선택형 학부모 공개 권한
- 학부모 문의 메시지
- 강사 우선 확인 화면
- 학생-코치 직접 대화
- 모바일 첫 화면에 맞춘 메신저형 학생-코치 대화 UI
- 사용자가 검토하고 직접 보내는 선택형 AI 문장 정리
- 목록 아이콘으로 여는 Notion식 역할별 사이드바 내비게이션
- 학생 기록·상담, 코치 기록 검토, 학부모 공개 요약, 관리자 운영 화면 뼈대
- 26개 핵심 테이블의 PostgreSQL 전방향 마이그레이션 설계
- 학생 본인·담당 코치·선택 공개 학부모·관리자 범위를 구분한 RLS
- 대화 참여자 검사와 AI 승인·일일 한도의 원자적 예약 함수
- 브라우저 로컬 저장
- 한국 시간 기준 실제 오늘로 초기화되는 일정과 재현 가능한 기준일 데모 데이터
- 학생이 현재 기기 저장 현황을 확인하고 2단계 확인 후 로컬 데이터를 삭제하는 흐름
- 모든 프로토타입 상태 변경을 localStorage에 먼저 저장하고 성공한 경우에만 화면에 반영하는 공통 계약
- 설치형 PWA 기반
- 올리브 기를 더한 포레스트·세이지 그린과 웜 아이보리·살구 오렌지 브랜드 팔레트

실제 로그인, PostgreSQL, 실시간 메시지 서버, OpenAI API, 파일 저장소, 푸시 알림은 아직 연결하지 않았습니다. SQL 파일은 설계 산출물이며 어떤 DB에도 적용하지 않았습니다. 역할 전환 메뉴는 개발 미리보기용이며 실제 인증이나 접근 통제를 대신하지 않습니다.

## 실행

```powershell
npm.cmd install
npm.cmd run dev
```

기본 주소는 `http://localhost:3000`이며 학생 화면인 `/student`로 이동합니다.

## 데이터와 보안 경계

- 현재 프로토타입의 앱 상태는 브라우저 `localStorage`, 작성 중인 일부 초안은 `sessionStorage`, 사진·영상 원본은 `IndexedDB`에 저장합니다.
- 할 일·일정·기록·컨디션·공개 설정·공부 세션·메시지는 localStorage 쓰기가 성공한 뒤에만 화면 상태를 바꿉니다. 저장이 거부되면 입력 화면을 유지하고 모든 역할 화면 상단에 기기 저장 실패를 알립니다.
- 학생은 `/student/privacy`에서 이 기기에 저장된 데이터 수와 첨부 용량을 확인하고 2단계 확인 후 삭제할 수 있습니다. 앱 상태 저장 실패 시 화면을 비우지 않으며, 초안이나 첨부 저장소 삭제가 일부 실패하면 재시도 범위를 알립니다.
- 기기 데이터 삭제는 현재 브라우저 origin의 프로토타입 데이터만 대상으로 합니다. 서버 계정·다른 기기·외부 캘린더나 파일은 삭제하지 않으며, 운영 계정 삭제 절차를 대신하지 않습니다.
- 학생-코치 대화도 같은 브라우저 안에서만 공유되며, 서로 다른 기기나 계정에는 전달되지 않습니다.
- 실제 학생 정보, 건강 정보, 성적, 계약·결제 정보는 입력하지 않습니다.
- Production 전 서버 기반 인증·RBAC·PostgreSQL·감사 로그가 반드시 필요합니다.
- 학부모 기본 권한은 문의 메시지이며, 출결·계약/결제·학업·실기는 학생이 항목별로 공개한 경우에만 표시합니다.
- 학생과 코치의 전체 대화, 멘탈 기록 원문, 민감한 건강·상담 메모, AI 질문 원문은 학부모에게 공개하지 않습니다.
- NORE API, webhook, 자동 데이터 전송은 추가하지 않습니다.

## 일정 도우미 원칙

현재 일정 도우미는 비용 없는 규칙 기반 해석기로 날짜, 시간, 제목과 분류를 정리합니다. 홈과 캘린더에서 보낸 모든 요청은 먼저 초안으로 보여주며, 사용자가 날짜·시간·제목을 확인하고 `이 일정 등록`을 눌러야 저장됩니다. 향후 OpenAI API로 교체하더라도 로그인·승인·일일 사용량 제한을 먼저 적용합니다.

일정 화면의 공부·운동·회복 할 일은 날짜가 있는 하나의 데이터로 관리합니다. 홈은 오늘 항목의 완료에 집중하고, 캘린더는 선택 날짜의 추가·삭제·완료와 전체 일정 조망에 집중합니다. 학생만 변경할 수 있고 코치는 읽기 전용입니다. 현재는 브라우저 로컬 저장 프로토타입이므로 실제 운영 전 서버 권한 검사와 PostgreSQL 저장이 필요합니다.

앱은 브라우저가 처음 상태를 복원할 때 한국 시간(`Asia/Seoul`) 기준 실제 오늘을 사용합니다. 고정 기준일의 샘플 데이터는 상대 간격을 유지해 오늘 주변으로 한 번 이동하지만, 사용자가 이미 만든 일정·기록 날짜는 날짜가 바뀌어도 자동 이동하지 않습니다. 서버 렌더링은 결정적인 기준일 상태를 유지하고 클라이언트 복원 뒤 전환해 시간대 차이로 인한 hydration 불일치를 피합니다.

두 로컬 assistant API는 `application/json`만 허용하며 선언된 크기와 실제 UTF-8 바이트 크기를 모두 제한합니다. 성공·오류 응답에는 private `no-store`를 적용합니다. 이 요청 경계는 실제 로그인이나 사용량 제한을 대신하지 않으며, 운영 연결 시 공통 세션·권한 검사와 서버 rate limit을 추가해야 합니다.

## 기록 입력 원칙

- 시스템 기록 항목은 항목별 허용 범위·소수 자릿수·고정 단위를 사용합니다.
- 사용자 정의 항목은 이름과 기본 단위를 필수로 하며 같은 영역의 중복 이름과 과도한 항목 생성을 차단합니다.
- 수동 기록은 유한한 10진수만 허용하고 미래 수행 시각, 잘못된 달력 날짜, 단위 변경을 저장하지 않습니다.
- 화면과 상태 변경 경계가 같은 검증 모듈을 사용합니다. 다만 이는 프로토타입의 데이터 품질 보강이며, 운영 DB 제약·서버 권한·코치 검증을 대신하지 않습니다.
- 구형 저장 상태에서 기준을 통과하지 못한 기록은 삭제하지 않고 `검토 필요`로 표시하며, 수정·확인 흐름이 구현되기 전까지 코치 최신 기록 요약에서는 제외합니다.

## 학생 홈과 내비게이션 원칙

- 홈에는 `오늘 상태 저장`, `오늘의 할 일`, `RP AI 도우미`만 표시합니다.
- 공부 타이머, 기록, 상담, 코치 대화, 공개 설정은 목록 아이콘으로 여는 사이드바에서 선택합니다.
- 밤 10시 이후에는 푸시 알림 대신 홈 상단에 작은 격려 문구를 표시합니다. 운영 알림은 사용자 동의와 서버 알림 인프라가 준비된 뒤 별도로 검토합니다.
- RP AI 도우미는 입시·운동 상담을 자동 판단하지 않고 담당 코치 대화 초안으로 연결합니다.

## 학생-코치 대화 원칙

- 직접 작성이 기본이며 AI 도움은 사용자가 선택합니다.
- 현재 AI 도움은 외부 모델을 호출하지 않는 비용 없는 규칙 기반 문장 정리입니다.
- AI는 초안만 만들고 자동 발송하지 않습니다. 사용자가 내용을 확인한 뒤 직접 보내야 합니다.
- 대화 전용 화면은 날짜 구분, 발신자별 말풍선, 외부 시간 표시와 한 줄 작성창을 사용합니다.
- 첨부 선택 시 파일 개수·크기·MIME뿐 아니라 JPEG·PNG·GIF·WebP·WebM·MP4·MOV의 실제 파일 시그니처가 선언 형식과 일치하는지 확인하고, 저장 직전에도 같은 검증을 다시 실행합니다.
- 첨부 원본을 저장한 뒤 메시지 상태를 localStorage에 먼저 영속화합니다. 상태 저장이 실패하면 새 원본을 보상 삭제하고, 앱 시작 시 메시지에서 참조하지 않는 IndexedDB 원본을 정리합니다.
- 저장된 원본은 표시 전에 메타데이터의 크기·MIME·종류와 파일 시그니처를 다시 확인하며 불일치하면 렌더링하지 않습니다.
- 시그니처 검사는 확장자 위장이나 단순 형식 불일치를 줄이는 프로토타입 경계입니다. 악성 파일 검사, 이미지·영상 완전 디코딩, EXIF 제거와 서버 검증을 대신하지 않습니다.
- 학부모는 학생-코치 대화를 자동으로 볼 수 없습니다.
- Production에서는 인증, 학생-코치 관계 권한, PostgreSQL 저장, 실시간 동기화, 읽음 상태와 알림이 먼저 필요합니다.

## HTTP 보호 경계

- 전체 경로에 `X-Robots-Tag`를 적용해 검색 색인·보관·미리보기 수집을 거부합니다.
- 학생·코치·학부모·관리자·캘린더 화면과 모든 API는 브라우저·공유 CDN에 저장되지 않도록 private `no-store`와 CDN 전용 no-store를 사용합니다.
- 이 헤더는 실제 인증을 대신하지 않습니다. 인증 연결 전 역할 화면과 API는 여전히 운영 배포 금지 상태입니다.
